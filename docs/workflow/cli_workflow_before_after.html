ImageJAI CLI workflow diagram — before vs after

BEFORE cli_agent_workflow.svg

1200 × 1600 portrait · 14 stacked text-boxes · no real strings
Problems
  • Two parallel lanes suggest two paths — really it’s one socket, two message kinds.
  • Zero real command names, event names, agent names, JSON, or :7746.
  • Portrait shape wastes README space; reader scrolls a long way for little payoff.
  • Every box requires reading 3 lines of prose. Nothing is glanceable.

AFTER cli_agent_workflow.v2.svg

1400 × 1500 landscape · internals exposed on every side · 16-step sequence · gate stages marked
What changed
  • Three exploded internal panels instead of three labels:
    • Agent workspace — CLAUDE.md, ij.py, pixels.py, probe_plugin.py, recipe_search.py, auditor.py, recipes/, references/ (60 docs).
    • ImageJAI — TCP listener, JSON parser, dispatcher, EDT marshaller, event bus, subscriber queues, ★ safety gate, audit log, privacy posture.
    • Fiji — macro engine, plugin set (Bio-Formats, MorphoLibJ, StarDist, TrackMate, CLIJ2, Weka), image stacks, Results table, ROI manager, dialogs, log, AI_Exports/.
  • 16-step worked example with numbered stops, EDT badge, and two ★ SAFETY GATE callouts at the exact moments it fires (after Fiji returns raw values, before the reply hits the wire).
  • Safety gate breakdown row: all 6 things the gate does — path tokenisation, OME-XML scrub, results-table tokenisation, free-text envelopes, vision-frame downsampling, audit row.
  • Pill row of the 9 supported agents stays at the top.
  • Subway-map cheat-sheet of real commands + events at the bottom.
  • "How to read this" legend at the very bottom for first-time viewers.

WORKED EXAMPLE example_3d_rings.svg

A real CLI agent flow when the user types "make a 3D render of the rings in channel 2" — 30 numbered steps, 7 phases, 3 safety-gate firings.
What this shows
  • Pre-flight panel (top): the user's vague prompt, the workspace files the agent loads (CLAUDE.md, ij.py, 3d-visualisation reference, 3d-spatial reference, recipes), and the 5-step plan it builds before any TCP traffic.
  • 7 phases labelled in the left margin: ORIENT · LOOK · PROBE · ISOLATE+ENHANCE · VERIFY · 3D RENDER · SAVE.
  • The agent investigates first: get_state → get_image_info → capture_image of ch2 → thinks (yellow) → only THEN starts changing the image. This is what stops the agent from being a parrot.
  • Real Fiji macros with real plugin names: Subtract Background, Tubeness (for ring/tubular enhancement), Otsu threshold, 3D Viewer, ImageJ3DViewer.setView, exportContent "WaveFront".
  • Three safety-gate stages marked ★ — every capture_image reply gets vision frames downsampled before it leaves Fiji.
  • Events stream throughout (dashed blue): macro.started, macro.completed, image.opened, dialog.opened, dialog.closed.
  • Outputs panel at the bottom: the 3D render preview (mock), the .obj mesh, the .png screenshot, the audit row in imagejai_audit.csv, and what stays in agent memory.
